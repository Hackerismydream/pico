# Pico 中文教程工作区（tutorial-zh）

这个目录是 Pico 中文教学/面试文档的版本化工作区。它服务两类读者：拿 Pico 准备 Agent 开发岗面试的学习者，和面试前复习的作者本人。它有意与 `docs/` 下的英文产品文档分离：产品文档描述当前系统「是什么」，这里基于明确的历史快照回答「怎么讲、怎么被追问、怎么答」。

> 生命周期：教学快照，不是当前实现真源。当前实现、证据与后续工作请先读
> [文档索引](../INDEX.md)、[项目状态](../project-status.md)、
> [能力证据表](../feature-evidence.md) 和 [Roadmap](../roadmap.md)。

## 写作硬规则

从旧版文档的教训（见 legacy-docs-review.md 第四、五节）直接推出，写任何一章之前先读一遍：

1. **先定版本基线再动笔**。每篇文档头部声明对应的 commit / tag。总览和分章必须描述同一个版本的系统；系统演进后，全套一起改或明确标注「本章基于 vX」。旧版总览与分章漂移一代，是面试里最容易被抓的破绽。
2. **数字单一出处**。所有对外引用的数字（测试数、压缩率、成本、通过率）只在一张「数字口径表」里维护：数值、口径定义、测量命令、出处 commit。简历、话术、章节正文一律引用，不复制。旧版三处数字互相矛盾（18.01% vs 22.2%、11 vs 10、v1/v2 混用）都是复制造成的。
3. **每章必须有一个可追问到底的数字**。哪怕是「每轮采样 12ms」这种小数字，也比「取舍是合理的」抗打。讲缓存必须给命中率，讲评测必须给通过率。给不出数字的章节说明还没到能写的时候。
4. **章节模板 v2（深入浅出骨架）**。每章按「具体场景与问题 → 最朴素做法怎么翻车 → 主流 harness 怎么做 → Pico 机制详解 → 取舍与为什么不做 X → 一次真实翻车 → 验证与数字 → 预演追问 → 口播稿 → 复习路径」推进。机制详解必须贴真实代码块和成品示例（prompt 长什么样、文件长什么样），承重名词第一次出现就给实物，结论句不许替代过程；长机制配一条时间线式的完整场景。追问每题给能直接说出口的完整答案，不许只写「见 XX 章」。引导句每章各写各的，禁止跨章逐字复用。
5. **教学正文与简历/话术素材分层**。正文不嵌简历 bullet；话术、简历版本、口径表各自单独成文，正文只链接。
6. **题库驱动选题**。每章的「预演追问」小节从 interview-question-bank.md 选题，优先覆盖高频榜和八条攻击路径。
7. **图必须可离线**。不依赖外部图床；用 mermaid/ASCII 或仓库内资源（注意 AGENTS.md §7 对二进制资产的限制，本目录只放文本）。
