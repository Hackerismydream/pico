# Pico 旧版（面向实习版本）飞书文档全量盘点

> 范围：飞书知识库「pico」节点下全部 39 篇文档（2026-07 抓取）。
> 目的：为新版（大升级版）Pico 的中文面试导向文档设计提供参照——旧版写了什么、怎么写的、哪些不好、哪些可借鉴。

## 一、知识库整体形态

这不是一套开源项目文档，是一个完整的「面试项目教学包」，服务对象是准备实习/校招的学员。全库分六个功能区：

| 区 | 篇目 | 功能 |
|---|---|---|
| 入口区 | 项目简历描述&代码&原始文档下载（含：怎么学 / 安装与模型使用 / 当前pico版本关系） | 简历弹药、代码入口、学习方法论、版本导航、降低跑通门槛 |
| 概念启蒙区 | 背景与目标 | LLM/推理模型/Agent/Harness 概念铺垫 + 动机叙事 |
| 设计章节区 | 00-全局总览 + 01~08 八个子系统章节 | 项目理解主体，面向「讲得出」而非「用得上」 |
| 面试武器区 | 90-逐字面试话术 / 91-面试题（更新中）/ 92-claude code相关 | 直接可背的答案层 |
| 实证区 | 99-面经（17 篇学员真实面经） | 信任背书 + 题库原料 |
| v3 区 | 关于v3说明 + 上下文压缩长文 | 新范式转型：对标主流 harness + 实验证据 |

三层版本梯度：mini-pico（教学最小骨架，有网站教程）→ main（主线学习版，对应 00-08 文档）→ v3（进阶参考版，「对标主流 + 做实验」路线，文档只发了一篇）。定位语：「mini-pico 负责入门，main 负责打地基，v3 负责给进阶面试提供参考模块」。

旧版 Pico 本体：单机本地 coding harness。核心链路 = CLI 装配（build_agent()）→ Pico.ask() 主循环 → ContextManager 五段式 prompt（prefix/memory/relevant_memory/history/current_request，预算+优先级裁剪）→ 工具统一边界 run_tool()（白名单 7 工具、参数校验、路径防逃逸、重复调用拦截、审批分级）→ LayeredMemory + DurableMemoryStore + checkpoint/resume（freshness、workspace 指纹）→ .pico/ 三类落盘（sessions/runs/memory）→ evaluator/metrics 固定 benchmark + FakeModelClient。v3 加了压力分级裁剪（tier0-3）、结构化 LLM/确定性双路摘要、配对 A/B 成本实验。

## 二、每篇写了什么（逐篇索引）

### 入口区
- **项目简历描述&代码**：两版简历 bullet（v1.0 初始 / v2.0 优化记忆模块）。每条 bullet 全量化：2 类模型后端、7 类工具、3 类运行工件；12 组配置平均压缩率 16.19%（最高 33.28%）；重复读文件 60 次→0；10 个恢复场景、漂移识别率 100%；固定回归任务三个 100%。附 gitee 仓库、运行截图、语雀 md 下载、夸克网盘归档。
- **怎么学**：学习方法论。核心序：先看简历描述反推追问 → 带问题读模块文档+代码 → 每章强制输出三件事（解决什么/怎么做/为什么不是另一种）→ AI 补问题清单 → 压成 30s/1min/3min 三种讲法 → 费曼式复述主链路 → 进阶必须亲手改一个点。附「零基础不用先看八股，build first」问答。
- **Pico 安装与模型使用**：provider 配置手册（DeepSeek 默认 / Right Code OpenAI-compatible / Anthropic-compatible / Ollama），.env 优先级、常见坑 Q&A。
- **当前pico版本关系**：三版本定位表 + 学习路径建议。

### 概念启蒙区
- **背景与目标**：hook（「用 GPT4o 达到 GPT5 家族能力」）→ 面试动机（2026/04 起后端/agent 面试逃不开 claude code/codex）→ LLM/推理模型/Agent/Harness 四概念辨析 + 厨师/后厨比喻 → 引导进入 01-08。

### 设计章节区（00 由本人精读，01-08 摘要见第五节子代理报告）
- **00-全局总览**：开篇契约（「读完你能回答这些问题」）→ 三条主线（控制面/状态面/证据面）→ 一条请求跑完整个系统的 9 步走 → 每个模块一节（图 + 文 + 代码位置）→ .pico/ 磁盘目录树具象化 → 关键代码入口表（10 个文件各配「为什么先看它」）→ 「只剩 15 分钟优先看 4 个文件」→ 10 分钟复习路径。

### 面试武器区
- **90-逐字面试话术**（51KB，全库最重）：按简历 bullet 组织。骨架 = callout 引简历原句 → 3-6 个追问 Q → 每 Q 逐字答案（总-分-总，关键句加粗）。覆盖：harness 定义、五层运行链路、工具治理、状态分层、复盘评测、上下文治理（含「12 组配置怎么设计的」「16.19% 不高为什么有价值」两个数字防御话术）、记忆系统（三组对照实验设计）、恢复机制（五类边界×2 场景）、三个 100% 的口径定义与「不证明什么」。还夹表达元教学（「长回答用总分总收尾，AI 时代面试官注意力涣散」）。
- **91-面试题**（更新中，烂尾）：一分钟项目介绍（是什么/为什么/怎么做/结果数字）、为什么不用现成框架（LangGraph 三条理由）、harness 怎么改进（过程评测/边界规则系统/可观测性三步）、code agent 生成代码的挑战（状态表示/修改准确性/过程稳定/验证闭环）。「指标问题」「主流agent框架改进方向」「如何保证AI代码生成质量」三节空着。与 90 存在大段逐字重复。
- **92-claude code相关**：单题标准答案（你看过 claude code 源码吗）：四点——loop 是状态机不是 REPL、工具 fail-closed、上下文是预算调度、先对齐再执行（plan mode），每点都回接 pico 对应设计，含「pico 还没实现 plan mode，我不夸大」的诚实话术。

### v3 区
- **关于v3及v3文档说明**：转型宣言。要点：复杂度与学习门槛的矛盾；代码大部分 AI 写（codex/claude code），架构人把控；文档新范式 =「从一个模块切入，跟各家 harness 对比，做实验，走完设计到评测闭环」；预告四个模块（上下文/Memory/autoresearch 式 system prompt 优化/harness benchmark）；「做完相当于一个新项目」。
- **从Novel Agent Harness到Pico：深入浅出Agent上下文压缩策略**（39KB，v3 唯一成文）：导读（白板比喻）→ 最朴素方案的五宗罪（悬崖式触发/全量摘要丢细节/token 估算不准/不分信息价值/用户输入与工具输出一刀切）→ 逐家拆解主流实现（Claude Code 四档压缩 Snip/MicroCompact/Collapse/AutoCompact + 断路器；Codex 本地/服务端 compact + 加密 blob + 探针实验还原 handoff prompt；OpenCode prune+summary）→ Pico 四阶段治理链路（动态预算公式、六 section 比例表、压力四 tier、双路摘要、fallback 链、「保护最近 2 轮为什么不是 1 或 3」）→ trade-off 章（50% vs 93% 利用率，引 Lost in the Middle 论文）→ 验证章（三 variant 配对 A/B、脚本/线上双模式、净收益公式、「可认领成本优化」三条件）→ 参考文献 4 篇。正文中间嵌了一条「参考简历写法」bullet（26.44% 数字）。

### 实证区（99-面经，见第六节子代理报告）

## 三、旧版怎么做的：可提炼的方法论

1. **简历驱动，反向组织**。整个体系的根不是架构文档，是简历 bullet。每条 bullet 配数字 → 90 里每条 bullet 配防御话术 → 00-08 提供理解地基。消费顺序 = 面试官的注意顺序。
2. **每个数字都有三层护甲**：怎么定义的（口径）、怎么测的（实验设计）、不证明什么（主动收缩）。「16.19% 不高为什么有价值」「三个 100% 不证明什么」是范本——预判质疑并把质疑变成展示严谨性的机会。
3. **复习友好性是一等公民**：开篇契约（读完能回答什么）、15 分钟只看 4 个文件、10 分钟复习路径、30s/1min/3min 三档讲法。这套设计承认用户是「面试前一晚的人」。
4. **诚实边界话术**：「pico 还没实现 plan mode，我不会夸大」「这层任务本来就不是测模型上限的」。教学员示弱的正确姿势。
5. **v3 新范式**：痛点 → 朴素方案缺陷 → 逐家拆主流 → 自家机制（真实公式/参数/文件名）→ trade-off → 验证标准。深度断层式领先 main 系列。
6. **面经回收闭环（设计上）**：学员实战 → 面经归档 → 反哺题库。机制正确，执行烂尾（91 停更）。

## 四、不好的地方

1. **90/91 大段逐字重复**：harness 定义、五层链路两篇完全一样。双份维护必然漂移，91 已烂尾（三节空白、标题挂「更新中」）。
2. **数字口径漂移，学员会自相矛盾**：简历 v2 已改 7082→5664（16.19%）、重复读 60→0；91 的一分钟介绍还在念 v1 旧数字（6964→5418、8→3、66.7%→100%）。00 说三条 provider 路径，简历写「2 类模型后端」。面试里被抓到数字对不上是致命伤。
3. **文本质量粗糙**：「这哥agent loop值得大家反复去可能啊」「这篇文档把大家把pico」「wrokspace」、双冒号「：：」、39 里残句「上画出来、能回答追问的程度」。收费教学产品有损专业感。
4. **资产链路脆弱**：图全部飞书图床（外链授权码会过期）、下载散在语雀+夸克网盘、代码在 gitee。任何一环失效都断链。
5. **章节↔话术无互链**：同一主题的理解版（01-08）和话术版（90）靠学员自己对，没有「这章对应简历第 N 条 / 90 的第 X 节」的索引。
6. **概念区有硬伤风险**：「GPT4o 达到 GPT5 家族能力」的 hook 在面试官耳里过于夸张；「OpenHarness」这类项目名经不起面试官现场搜索。
7. **面经区归档随意**：命名不统一（有的带日期有的不带）、多篇只有几百字节的裸问题清单、没有结构化字段（岗位/轮次/结果），题库回收停滞。
8. **文体混杂**：v3 长文正文中间插「参考简历写法」，教学叙事和简历素材没分层——这正是新版文档要用「一等公民产出分离」解决的问题。
9. **91 空节暴露组织问题**：按「想到的问题」增量堆，而不是按固定题库结构预留框架，停更后就是烂尾楼。
10. **总览与分章版本漂移（一致性问题里最严重的）**：00-总览描述的系统比 01-08 新一个版本——总览讲 DurableMemoryStore/promotion gate，05 章完全没提；总览讲恢复时比对 freshness/指纹/工具签名，07 章却明说「resume 还没有更复杂的一致性检查」；总览讲工具执行前后 workspace 快照，03 章的六步闸口里没有这一步。面试官先读总览再读分章会直接抓到矛盾。
11. **数字内部矛盾**：06 章写平均 prompt 6964→5418 又写「平均压缩率 18.01%」——按前者算是 22.2%，两种口径（各配置压缩率均值 vs 均值的压缩率）无任何说明；03 章说「11 个治理场景」但列出的是 3+5+2=10；05 章 66.7%→100% 实际是 8/12→12/12，样本小到不该用百分号，轮次和方差全文未提。
12. **断言无证据集中在 01/02/04/08**：01、02 全篇零测试引用零数字；04 讲了完整缓存链路却一个 cached_tokens 实测值都没有（讲缓存不给命中率等于自曝没跑过）；08 是评测章，通篇没有一个 pass rate。
13. **模板句复用到可检索的程度（AI 痕迹）**：「问题可以压成一句话：」8/8 篇、「这里真正要回答的是四件事：」6/8 篇（子问题恰好都是四条，模板凑数）、「我会优先补三件事。」6/8 篇、「这些都不是 bug，是下一步可以继续做的空间」两篇逐字重复、「先把 X 做稳，比先做复杂 Y 更重要」式段末升华句多篇复读。
14. **章号残留**：08 章里两处写「所以 09 这一层…」（上一版编号残留）；06 章里写「06 这一章不展开记忆设计细节」实际指的是 05 章。

## 五、01-08 设计章节详析

### 5.1 逐篇一览

| 章 | 主题与核心机制 | 证据状态 |
|---|---|---|
| 01 仓库上下文 | WorkspaceContext 七字段基线（字段/来源/为什么要带 三列表钉死）、白名单文档扫描（4 类文件、1200 字符截断）、fingerprint 判定 prefix 重建；有全系列最像真实面试对答的「为什么不预加载整仓」三层论证 | 零测试引用、零数字 |
| 02 主循环 | ask() 建 run 的完整链路、感知/决策/落地/记录四阶段循环、parse() 三分类（tool/final/retry）、attempts 与 tool_steps 区分（附诊断读法）、status 与 stop_reason 分开存 | 零测试引用、零数字（最核心的一章证据最薄） |
| 03 工具 | 全系列最扎实。六工具表（含风险级）、run_tool() 六步闸口完整代码、逐工具校验规则（timeout 1-120s、patch old_text 唯一命中）、resolve()+commonpath 防符号链接逃逸、delegate 四条约束、测试文件↔覆盖点对应表 | 11 个治理场景数字（但列出只有 10） |
| 04 提示词与缓存 | PromptPrefix 五字段表、refresh_prefix() 判断主线、失效条件正反两列、缓存链路追到 complete() 与 usage 回程 | 指标只有名字没有值；无图 |
| 05 会话记忆 | 开篇压预期（不做知识库）、四层记忆逐层配代码、freshness 哈希失效机制、retrieval_candidates() 可解释排序、update_memory_after_tool() 绑工具链生成 | 全系列最强验证：on/off/irrelevant 三臂对照 + 测试逐条对应；但 8 键结构只解释了 4 个 |
| 06 上下文瘦身 | 数据密度最高。四层瘦身（入口裁剪五处上限表、memory 自限额、relevant top-3 平分预算、history 新旧分层 900/60）、section 预算表（总 12000）、裁剪顺序、「current_request 永远不裁」核心不变量；诚实指出 FLOORS 定义了但没用 | 12 组配置、6964→5418、18.01%/35.63%（口径矛盾见第四节） |
| 07 状态与恢复 | 核心论点一句话：session 答「还能不能继续干」，run artifact 答「刚才发生了什么」；两张字段表 + 三份工件分工论证 + trace 追加写抗中断论证 | 测试覆盖点列出（含 secret 脱敏）；无数字；与总览版本冲突 |
| 08 评测 | 任务合同 JSON 完整样例、fixture copytree 防污染、FakeModelClient 拆分 harness 正确性与模型波动、四条件与门判定、失败四分类、「不同机制不能用同一个大指标」（全系列思辨性最强段落） | 通篇没有一个 pass rate |

### 5.2 共同骨架（8 篇严格同构的九段模板）

背景（压掉错误预期）→ 这篇要解决什么问题（一句话 + 「四件事」bullet）→ 机制长什么样（表格/结构体先行）→ 机制展开（why 型标题：一段解释 + 一段代码 + 一句设计点）→ 这一层怎么被验证（单测/实验两类，仅 5/8 篇有）→ 目前没做什么（3-5 条边界 + 「这些不是 bug」）→ 继续往下做优先补什么（「三件事」）→ 面试里怎么讲这一层（150-250 字第一人称口播 blockquote）→ 总结（3-5 句，基本是引言复述）。

### 5.3 叙事风格

- 口语化中偏高，但是「技术博客口语」：句长稳定 20-45 字，第二人称频繁，真口语碎句只有 03 结尾一处 PS。
- 比喻少而克制（全系列约 6 处，全是功能类比：工作手册/小仪表盘/快照/不走一把大剪刀），长比喻只在系列外的「背景与目标」（厨师/后厨）。
- 代码引用双轨：平均每篇 5.5 个 6-15 行片段（大量 `...` 省略），文字点名一律带模块路径，行内反引号极密——「哪些是代码里真实存在的东西」扫读可辨。
- 段落极短（中位 1-3 句），视觉像笔记不像文章。
- 图：6/8 篇各 1 张飞书内网流程图，alt 全空（外部读者拿到 markdown 是 6 个 404）；最需要图的 04（前缀失效）、05（记忆分层失效）恰好没图。

### 5.4 好的手法（新版沿用）

1. 每章一句可背的命题（「问题可以压成一句话」的位置保留，引导句换掉）。
2. 「为什么不做 X」独立成节且答案分层（01 预加载三层论证、06 粗暴截断论证）——直接就是面试防守弹药。
3. 表格定义对象、代码块证明存在，分工明确。
4. 主动列「目前没做什么」+「这是边界不是缺陷」。
5. 验证一节把测试文件和行为逐条对应（比「有单测覆盖」强一个量级）。
6. 05 的 on/off/irrelevant 三臂对照——全系列唯一排除了「只是多塞了点上下文」混淆变量的实验设计。
7. 08 的分机制口径论（上下文看压缩率、记忆看重复读取、安全看拦截、provider 才看 pass rate）。
8. 每章末尾可直接背的口播 blockquote。

### 5.5 面试视角的缺口（每章 1-2 个文档没备弹药的追问）

- 01：白名单文档 1200 字符截断切掉关键约束怎么办（头部截还是有优先级）？每轮 git 采样在大仓库耗时多少（「轻量缓存」唯一需要证明的地方，无数字）？
- 02：max_steps/max_attempts 默认值和依据？模型调用本身失败（超时/429/断连）走哪条分支——parse() 三分类里没有异常态。

### 6.3 面试官的八条攻击路径（新版文档必须逐条备弹药）

1. **真实性拷问（是不是 toy）**：「是你自己写的吗？」（三家公司同款）、「你平时用它跑真任务吗？跑一个任务多长时间？」「你的日均 token 消耗量是多少？」「部署在哪里？」——用使用量和 token 账单反查项目是否真在跑。
2. **造轮子质疑**：「为什么不用 GitHub 开源的？」「既然有 Claude Code / Agent SDK，Harness 工程是不是做完了？」「如果公司里真做 Harness，你会从头重写还是基于现有方案？」——还会下沉到子模块（「run trace 为什么不用现成工具？」）。
3. **横向对标**：「和行业 SOTA 的差距在哪？」「pico 的上下文管理和 Claude Code 比优缺点？」「CC 源码泄漏你看过吗，有没有参考？」
4. **指标严谨性**：「简历上 16.19% 怎么来的？」（实际考：有没有可复现 benchmark）「这个评测在测模型还是测 Harness？」「为什么用 FakeModelClient？」「记忆召回准确度怎么评估？」
5. **规模压测**：「5000 个工具怎么精准调用？」（连追 4 层：ToolCard/运行时路由/为什么工具 RAG 不够/相似工具多怎么办）「一万行的类文件读取直接超限怎么办？」「用户只输入一个 hi，prompt 长什么样、占多少 token？」（反向压测固定开销）。
6. **失败路径拷问**：CVTE 整场 13 题里 6 题是「X 失败了怎么办」——LLM 超时、循环调用、没调对工具、prompt 被错误裁剪、恢复失败。还有精确定义逼问：「read 同一文件四次算重复读取吗？」
7. **定义边界拷问**：「什么条件下才算 Agent 原生应用？」「你说 Agent 有自己的决策，决策是什么意思？」「Freshness 校验是什么意思？」
8. **商业落地质疑**：「agent 有 1%-5% 不稳定性，怎么说服甲方采用？」「这个项目的价值在哪里？最后解决了吗？」

- 小鹏一面单列「暴露出来要补的点」5 条：Agent 原生定义、业界方案与 Pico 的关系、怎么讲成 Harness 机制而非个人项目、后端一致性/高并发、K8s 基础。
- 字节：/btw 指令题当场没答上（事后靠 AI 分析源码补答案）；skill/MCP 不支持只能承认；plan mode 缺失「我不会夸大」。
- 多处「不能说成现状」的自我约束记录：审批超时队列不存在、subagent 是 v3 才有、LSP/tree-sitter 是未来增强、AGENTS.md 无多层继承、write_file 回读只是纪律不是强制 gate。
- 指标口径偏软被抓：16.19% 是字符级压缩率不是 token 级。
- 隐私题第一反应答错：「本地项目所以没隐私问题」被「接远程模型代码不还是发出去了」击穿，被迫改口诚实承认。

## 七、对新版文档的启示

1. **沿用**：简历驱动反向组织；数字三层护甲；开篇契约 + 分钟级复习路径；诚实边界话术；「对标主流 → 自家机制 → trade-off → 验证」的 v3 四段式（与新版的证据文化天然同构——「可认领成本优化」三条件就是新版 evidence discipline 的口语版）。
2. **修正**：话术层单一事实源（题库只在一处维护，简历数字用引用而不是复制）；数字口径表（版本×指标×出处一张表，全库引用）；教学正文与简历/话术素材分层；面经结构化归档（岗位/轮次/问题/结果字段）。
3. **新版独有的机会**：旧版的「实验」深度止步于 12 组配置/10 个场景的自建对照；新版在 PR #47 有 3311 条确定性测试，PR #56 增至 3567 条 retained，通过 V-* 验证门、TokenWise 50.7% 历史 A/B、evolver sealed-split 统计门把证据等级提高一个量级，文档范式可以从「我做了实验」升级到「我建了证据体系」。
4. **梯度接位**：mini → main → v3 → 新版。新版文档需明确自己在梯度里的定位（v3 说过「做完相当于一个新项目」——新版就是那个新项目）。
5. **三条硬规则**（从 01-08 的教训直接推出）：
   - 保骨架，换句式——九段模板是对的，逐字复用的引导句（一句话/四件事/三件事）必须每章各写各的；
   - 每章必须有一个可追问到底的数字——哪怕是「每轮 workspace 采样 12ms」「prefix 复用率 78%」这种小数字，也比「取舍是合理的」抗打；讲缓存必须给命中率，讲评测必须给通过率；
   - 先定版本基线再动笔——总览和分章描述同一个版本的系统，全库数字只有一个出处。
6. **题库直接换弹**：第六节的高频榜和八条攻击路径就是新版每章「预演追问」小节的选题清单。特别是三类旧版答不好的题，新版有天然优势：指标严谨性（V-* 门与可复现命令）、真实性拷问（tracing/usage 有真实账单可秀）、规模压测（多 channel/Gateway/Cron 本来就是工业形态）。「为什么自己写」这道 7 次高频题，新版叙事下需要重新准备一份标准答案。
