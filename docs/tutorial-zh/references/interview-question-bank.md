## 二、面试官的八条攻击路径

1. **真实性拷问（是不是 toy）**：「是你自己写的吗？」（三家公司同款措辞）、「你平时用它跑真任务吗？跑一个任务多长时间？」「你的日均 token 消耗量是多少？」「部署在哪里？」——用使用量和 token 账单反查项目是否真在跑。
2. **造轮子质疑**：「为什么不用 GitHub 开源的？」「既然有 Claude Code / Agent SDK，Harness 工程是不是做完了？」「公司里真做 Harness，你会从头重写还是基于现有方案？」也会下沉到子模块：「run trace 为什么不用现成工具？」
3. **横向对标**：「和行业 SOTA 的差距在哪？」「和 Claude Code 比优缺点？」「CC 源码泄漏你看过吗，有没有参考它的设计？」
4. **指标严谨性**：「简历上 16.19% 怎么来的？」（实际考有没有可复现 benchmark）「这个评测在测模型还是测 Harness？」「为什么用 FakeModelClient？」「记忆召回准确度怎么评估？」
5. **规模压测**：「5000 个工具怎么精准调用？」（连追四层：ToolCard 设计 → 运行时路由 → 为什么工具 RAG 不够 → 相似工具很多怎么办）「一万行的类文件读取直接超限怎么办？」「用户只输入一个 hi，prompt 长什么样、占多少 token？」（反向压测固定开销）
6. **失败路径拷问**：LLM 超时、循环调用、没调对工具、prompt 被错误裁剪、恢复失败（CVTE 一场 13 题里 6 题此类）。精确定义逼问：「read 同一文件四次算重复读取吗？」「审批超时怎么处理？」
7. **定义边界拷问**：「什么条件下才算 Agent 原生应用？」「你说 Agent 有自己的决策，决策是什么意思？」「Freshness 校验是什么意思？」
8. **商业落地质疑**：「agent 有 1%-5% 不稳定性，怎么说服甲方采用？」「这个项目的价值在哪里？最后解决了吗？」

## 四、候选人实际失分记录（新版话术要重点补的）

- 隐私题第一反应「本地项目所以没问题」，被「接远程模型代码不还是发出去了」击穿，被迫改口诚实承认 (24)。
- 16.19% 是字符级压缩率不是 token 级，口径被抓 (24)。
- /btw 指令题当场没答上，事后靠 AI 分析源码补答案 (27)。
- skill/MCP 不支持、plan mode 缺失、审批超时队列不存在、subagent 是 v3 才有——多处只能「承认 + 不夸大」(27/35/36)。
- 「LSP/tree-sitter/调用图属于未来增强，不能说成现状」「AGENTS.md 没有多层继承，不要说成 CC 那种完整规则体系」「write_file 回读是纪律不是强制 gate」——36 号面经里成体系的「不许吹」清单。
- 使用量类问题（跑多久 / 日均 token）全批面经零准备，是唯一无法靠架构话术搪塞的题型 (33)。
- 小鹏一面自评 5 条待补：Agent 原生定义、业界方案与 Pico 的关系、怎么讲成 Harness 机制而非个人项目、后端一致性/高并发、K8s 基础 (34)。
- 24 号面经整篇是「表面上问什么 / 实际考什么」复盘表，说明当场按表面意思答了（例：把「压缩率怎么测」当算术题答，而不是可复现 benchmark 题）。
