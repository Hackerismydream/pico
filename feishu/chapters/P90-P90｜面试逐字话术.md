# P90｜面试逐字话术

这里不是“背标准答案”的题库。每道回答都按同一顺序组织：先用一句话给结论，再画执行链，接着讲失败路径、权衡和证据，最后主动收住能力边界。面试官只要结论时就停在核心直答；继续追问时再展开，不要一上来倾倒整章术语。

## 使用方法

1. 先读 [总话术](https://icnoljnkix43.feishu.cn/wiki/H9rewOY10ixocdkYCuwcIHqjneY)，练熟极简版、简版、标准版、完整版和白板推演版的共同主线。
2. 打开 [问题地图](https://icnoljnkix43.feishu.cn/wiki/NrUbwRyGeiUd1pk5R8WcxKuNn50)，按 canonical ID 找到问题的来源措辞、当前问法、模块、源码证据和不能越过的边界。
3. 按模块练下面五份逐字稿。每题先说“直答”，对方点头后再进入“详细展开”和“挑战追问”。
4. 用 [源码阅读练习](https://icnoljnkix43.feishu.cn/wiki/GIjHwgvMQiBSftkideacsQRKnGn) 亲手复现至少一条 happy path 和一条失败路径。说不出对象所有权和终态，就还没有真正掌握。
5. 最后再写 [简历](https://icnoljnkix43.feishu.cn/wiki/IFlbwWf6Bi5a8xkK5k5cK2JunXc)。简历数字、逐字稿数字和证据台账必须是同一口径。

## 覆盖口径

- 题目台账共有 105 个 canonical group；六份稿件合计覆盖 105/105。
- 来源层保留 344 条 occurrence。同一个知识点在不同面试里换问法时，共享一个 canonical，不靠重复答案制造“覆盖率”。
- 任何带方括号的个人经历都必须在面试前替换成候选人的真实经历；没有亲自做过的事情不能把系统实现改写成个人贡献。
- 架构问题先讲当前实现，再讲可选改进。不要把设计建议、未启用组件或没有合格工件的数字说成已经上线的结果。
